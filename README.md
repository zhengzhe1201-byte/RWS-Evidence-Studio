# RWS Evidence Studio

面向真实世界研究团队的静态交互 Demo。产品定位不是“自动给医学结论”，而是帮助统计师、研究医生、流行病学人员和数据管理人员，把原始业务数据转成可审计、可复算的探索性研究报告。

## 完整研究流程

研究方案预设 → 变量映射 → 队列构建 → 数据治理 → 分析方案推荐与人工确认 → 效应估计 → 敏感性分析 → 可导出研究报告。

当前医疗AI定位为 **L2 智能辅助**：系统可以整理研究问题、执行确定性规则、计算统计结果并生成报告初稿；研究方案、临床语义、治理规则、统计方法和正式结论仍由专业人员确认。

## AECOPD 演示场景

Demo 使用卜彦斌提供的 AECOPD 虚拟 CSV，研究索引住院期间 Tiotropium 暴露与出院后30天当前数据源记录的全因再入院之间的关联。

- 总患者：200人；最终研究队列：181人。
- Tiotropium组：93人，8例30天再入院，粗风险8.6%。
- 对照组：88人，14例30天再入院，粗风险15.9%。
- 建议主分析：IPTW（ATE口径）。
- 支持性分析：多变量 Logistic 回归。
- 敏感性分析：1:1倾向评分匹配、14天结局、排除计划再入院、替代PS截断。
- 描述性参照：粗分析。

统计方法页面同时提供“研究问题 → 方法 → 前提 → 输出”的选择导航：描述性统计、t/秩和/卡方/Fisher、多变量Logistic、Cox/KM、PSM/IPTW均说明适用条件和当前可执行状态。表1连续变量按分布报告均值±SD或中位数[IQR]，分类变量报告n（%），基线平衡以SMD为主，不用P值机械筛选混杂因素。

系统明确标记当前没有接入的外院结局、GOLD、CAT、吸烟、肺功能和依从性，不使用虚构值补齐这些数据。ICU入住和索引住院合并诊断数量目前仅作为候选严重度代理，正式研究需核对其是否早于首次Tiotropium处方。

## 本地运行

项目为纯 HTML、CSS 和 JavaScript，无构建步骤。可直接打开 `index.html`，或使用静态文件服务器：

```powershell
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 发布

整个目录可直接部署到 GitHub Pages、Netlify、Vercel 或其他静态托管平台。GitHub Pages 发布时，仓库根目录应直接包含 `index.html`、`app.js`、`styles.css` 等文件。

## 结果边界

全部患者均为虚拟数据。统计调整只能处理已测量且时间顺序正确的基线变量，不能消除未测量混杂；单一住院数据源可能漏掉外院再入院。IPTW和PSM当前展示点估计，正式推断仍需稳健标准误、Bootstrap或与匹配结构相符的区间估计。Cox/KM仅在时间零点、随访来源、删失、竞争风险及比例风险假设可以明确时启用。结果不构成正式真实世界证据、医学建议或因果结论。
